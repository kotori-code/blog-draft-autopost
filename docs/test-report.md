# テスト報告書 — ブログ記事 下書き自動作成

実施日: 2026-11-13〜14

## 1. 目的

- スプレッドシートの操作から WordPress への下書き保存まで、仕組みが正しく動くかを確かめる
- AI が作る記事が、要件（2,000〜3,000 字・理想記事のトーン・独自性・説明文 120 字以内）を満たすかを確かめ、指示文とモデルを決める

## 2. テストの環境

| 項目 | 内容 |
|---|---|
| スプレッドシート | 「記事作成」「共通設定」「個別設定」の 3 シート（本番と同じ構成） |
| 文章生成 | OpenAI API（gpt-4.1-mini → gpt-6.1-sol） |
| WordPress | 疑似案件のため実サイトなし。シート上は `WP_MOCK`（保存できたことにする）、送信の中身は手元の仮の WordPress で確認 |
| 記事の確認 | `TEST_OUTPUT_SHEET_URL` の書き出し先に、本文・説明文・字数を書き出して読む |

## 3. 仕組みのテスト

| URL 違い | 404・「WP_BASE_URL が違うか…」 | ✓ |

| 届いた中身 | status が draft・タイトル・見出し 4 つ・説明文（抜粋）・専用ユーザー | ✓ |

## 4. 記事の品質テスト（5 本）

| # | キーワード | モデル | 本文の字数（見出しを除く） | 判定 |
|---|---|---|---|---|
| 1 | 勤怠管理 エクセル 限界 | gpt-4.1-mini | 約 1,100 字 | ✗ |
| 2 | 勤怠管理 エクセル 限界 | gpt-4.1-mini（指示を追加） | 約 1,270 字 | △ |
| 3 | 有給休暇 管理 方法 | gpt-6.1-sol | 約 2,580 字 | ✓ |
| 4 | テレワーク 勤怠管理 課題 | gpt-6.1-sol | 約 2,800〜2,900 字（概算） | ✓ |
| 5 | 36協定 残業時間 上限 | gpt-6.1-sol | 3,000 字前後（概算） | ✓ |

### 4-1. 1 本目で見つかった問題

トーン（書き出しの流れ・見出しの形・結び）は理想記事どおりだったが、次の 5 つの問題があった。

| 問題 | 内容 |
|---|---|
| 字数が足りない | 約 1,100 字で、要件の半分。理想記事（約 960 字）の長さまでまねた |
| 理想記事と中身がほぼ同じ | 3 つの論点も例も理想記事と同じ。同じブログ内で検索順位を奪い合うおそれ |
| 作り話の事例 | 「ある会社では…対応に数日かかった」など、根拠のない話を事実のように書いた |
| タイトルと中身のずれ | タイトル・説明文で「選び方」と言っているのに、本文に選び方の見出しがない |
| 同じ言葉の繰り返し | 「工数」が 9 回出てくる |

### 4-2. 指示の追加（2 本目）

AI への指示に 5 つのルールを加えた（`gas/Body.js`）。

1. 長さの目安（導入 300 字前後・各見出し 600〜800 字・まとめ 300 字前後）。理想記事の長さはまねない
2. 理想記事からまねるのは文体と組み立て方だけ。論点・例は変える
3. 実在しない会社・人・数字・事例を事実として書かない。例は「例えば〜の場合」と仮定の形にする
4. タイトルで約束した内容は、必ず見出しで扱う
5. キーワードを不自然に繰り返さない

結果: **作り話だけが直り、残りの 4 つは直らなかった**（字数 1,270 字、論点は理想記事のまま、選び方の見出しなし、「工数」9 回）。

### 4-3. 原因の切り分け（3 本目）

2 つの原因が考えられたため、同時に変えて試した。

| 考えた原因 | 変えたこと |
|---|---|
| 安いモデルは長い指示を守りきれない | モデルを gpt-6.1-sol に上げる |
| キーワードが理想記事と同じテーマで、似た内容になりやすい | 別のテーマ（有給休暇 管理 方法）で試す |

結果: **5 つすべてを満たした**。紙・エクセル・専用システムを比べるという、理想記事にない切り口になった。法律の説明（年 5 日の取得義務、半日単位と時間単位の扱い、取得率の出し方など）も正確だった。

小さな問題が 2 つ残った。

| 問題 | 直し方 |
|---|---|
| 比較の記事なのに見出しが「落とし穴①」 | トーンのルールを「〇〇①：〜（〇〇は内容に合う言葉）」に変更 |
| 導入で読者が急に「経営者や IT 担当者」に変わる | 「共通設定」の読者（経営者・IT 担当者）とトーンのルール（労務・総務の担当者）が食い違っていた。読者を「労務・総務の担当者（経営者が読んでも分かるように）」にそろえた |

### 4-4. 確認（4・5 本目）

| # | 確かめたこと | 結果 |
|---|---|---|
| 4 | 見出しの言葉が内容に合うか | 3 ステップの記事で「ステップ①：〜」になった ✓ |
| 4 | 読者がぶれないか | 労務・総務の担当者で一貫 ✓ |
| 5 | 数字の多いテーマで正確か | 月 45 時間・年 360 時間、特別条項の年 720 時間・単月 100 時間未満・2〜6 か月平均 80 時間以内、休日労働を含む／含まないの区別、罰則（拘禁刑）、計算例まで、確認した範囲で誤りなし ✓ |
| 5 | 見出しの言葉 | 間違えやすい点の記事なので「落とし穴①」✓（内容に合わせて使い分けられている） |

### 4-5. 説明文（メタディスクリプション）

| # | 説明文 | 字数 | 判定 |
|---|---|---|---|
| 1 | 勤怠管理をエクセルで行う際の限界や集計ミスによる工数増加の問題点を解説。中小企業向けに効率化のポイントと選び方を整理します。 | 約 60 字 | △ 本文に無い「選び方」を含む |
| 3 | 有給休暇の管理方法を、紙・エクセル・専用システムの3つで比較。年5日の取得義務や取得率の集計で見落としやすい点と、中小企業に合う選び方を解説します。 | 約 80 字 | ✓ |
| 5 | 36協定の残業時間上限は「少しなら超えてよい」のでしょうか。特別条項の条件、違反時の罰則、休日労働・複数月平均の注意点を、労務・総務担当者向けに具体例で解説します。 | 約 85 字 | ✓ |

いずれも 120 字以内。gpt-6.1-sol では、キーワードを最初の文に入れ、本文の中身と一致していた。

## 5. モデルの比較と費用

| | gpt-4.1-mini | gpt-6.1-sol |
|---|---|---|
| 字数 | 要件の半分ほど | 要件どおり |
| 指示の守り方 | 5 つのうち 1 つ | 5 つすべて |
| 1 本あたりの費用（料金表からの試算） | 約 1 円 | 約 7 円 |
| 月 13 本の費用（試算） | 約 15 円 | 約 100 円 |

**gpt-6.1-sol を採用する**（初期値を変更済み）。月 100 円前後で、提案書の「月額 数百円」に収まる。費用は、料金表と記事の長さから出した試算。

## 6. 結論

- 仕組み（シート → AI → WordPress 下書き → シートへの結果）は、想定どおりに動く
- 記事は gpt-6.1-sol と今の指示文で、要件（字数・トーン・独自性・説明文）を満たす。提案書の「60〜70 点の下書き」を上回る出来で、担当者の手直しは少なく済む見込み
- 安いモデルでは指示を足しても直らない問題があり、**モデル選びは費用より品質で決めるべき** ことが分かった

## 7. 残っていること

| 項目 | 対応 |
|---|---|
| 本物の WordPress での保存 | 納品先のサイトで、専用ユーザーで下書きを 1 本保存して確認する（着手前の確認） |
| 法律の内容の確認 | 労務の記事は、公開前に担当者か社会保険労務士が確認する（運用で対応） |
| 字数が 3,000 字を超えることがある | 続くようなら、各見出しの目安を 600〜800 字から 500〜700 字に下げる |
| まとめの段落が改行だけで区切られることがある | WordPress では 1 段落にまとまる。下書きの確認時に整える |
| 理想記事と同じテーマのキーワード | 似た内容になりやすい。キーワードを選ぶ段階で、既存記事と重ならないか担当者が確認する |
