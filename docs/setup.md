# セットアップ手順

## 1. プログラムを貼り付ける

1. スプレッドシートを開き、上のメニューの **拡張機能 > Apps Script** を開く
2. 左の「ファイル」の **＋ > スクリプト** で、次の 9 つのファイルを作り、`gas/` の同じ名前のファイルの中身を貼り付ける
   - `Config` / `Code` / `Settings` / `OpenAi` / `Titles` / `Body` / `WordPress` / `TestOutput` / `Setup`
   - 最初からある `コード.gs` は、中身を消して `Config` の内容を貼っても、削除してもよい
3. 保存（💾 のアイコン）する

## 2. シートを作る（初回だけ）

1. 上の関数の選択欄で `setupSheets` を選び、**実行** を押す
2. 初回は Google アカウントの許可を求められるので、自分のアカウントを選んで許可する
3. スプレッドシートに戻ると、「記事作成」「共通設定」「個別設定」の 3 シートができている

- すでに中身があるシートは書き換えません。作り直したいときは、そのシートを削除してから `setupSheets` をもう一度実行します
- `setupSheets` は、チェックボックスを押したら動く仕組み（トリガー）の登録もします。トリガーだけ登録し直したいときは `setupTriggers` を実行します

## 3. OpenAI・WordPress の設定（スクリプトプロパティ）

Apps Script の左の **⚙ プロジェクトの設定** の一番下「スクリプト プロパティ」に追加します。

| プロパティ | 値 | 必須 |
|---|---|---|
| `OPENAI_API_KEY` | OpenAI の API キー | 本番では必須 |
| `OPENAI_MODEL` | 使うモデル名（省略すると `gpt-4.1-mini`） | 任意 |
| `OPENAI_MOCK` | `true` にすると OpenAI を呼ばず、テスト用のタイトル・記事を返す | 任意（API キーが無いときの動作確認用） |
| `WP_BASE_URL` | WordPress サイトの URL（例: `https://example.com`） | 本番では必須 |
| `WP_USERNAME` | 記事保存用の専用ユーザーのユーザー名 | 本番では必須 |
| `WP_APP_PASSWORD` | そのユーザーのアプリケーションパスワード | 本番では必須 |
| `TEST_OUTPUT_SHEET_URL` | 記事本文と説明文の書き出し先のスプレッドシートの URL | 任意（記事の中身を確認するとき） |
| `WP_MOCK` | `true` にすると WordPress に送らず、保存できたことにする（URL は `https://example.com/...`） | 任意（WordPress が無いときの動作確認用） |

API キーも WordPress も無いときは、`OPENAI_MOCK` と `WP_MOCK` を両方 `true` にすると、シートの動きを最後まで確かめられます。

## 4. シートの見方

| シート | 見出しが青の列 | 見出しが灰色の列 |
|---|---|---|
| 記事作成 | 担当者様が入力・操作する（キーワード・サブキーワード・補足メモ・チェックボックス・採用する案） | 自動で書き込まれる（作成日・公開日・タイトル案・タイトル・URL・エラー内容） |
| 共通設定 | 「内容」を自由に書き換える | 項目名と説明 |
| 個別設定 | 「指示文」を自由に書き換える | 種類と使える差し込み |

- 灰色の列を手で書き換えようとすると、警告が出ます
- 「ステータス」だけは手で変えられます。記事を公開したら「公開済」にすると、公開日が自動で入ります
- 「共通設定」「個別設定」を書き換えたら、下の「反映する」にチェックを入れます。次に作る記事から新しい内容が使われます（反映するまでは、前に反映した内容が使われます）

## 5. タイトル 5 案の作り方

1. 「記事作成」シートにキーワード（必要ならサブキーワード・補足メモ）を入れる
2. 「タイトル5案を作成」にチェックを入れる
3. ステータスが「作成中」→「タイトル案あり」に変わり、「タイトル案」に 5 案が入る（チェックは自動で外れる）
4. 使う案の番号を「採用する案（1〜5）」で選ぶ

うまくいかないときは、ステータスが「エラー」になり、「エラー内容」に理由が書かれます。直してから、もう一度チェックを入れてください。

## 6. 本文の作り方（WordPress に下書き保存）

1. 「採用する案（1〜5）」で番号を選んでから、「本文を作成」にチェックを入れる
2. ステータスが「作成中」→「作成済」に変わり、「タイトル」「WordPress URL」（下書きの編集画面）「作成日」が入る
3. WordPress URL を開いて下書きを確認し、画像を設定して公開する
4. 公開したら、ステータスを「公開済」に変える（公開日が自動で入る）

- 「作成済」「公開済」の行は、もう一度チェックを入れても作り直しません（同じ記事が 2 本できるのを防ぐため）
- 記事は必ず「下書き」で保存され、自動では公開されません

## 7. 記事本文と説明文を別のスプレッドシートに書き出す（確認用）

スクリプトプロパティ `TEST_OUTPUT_SHEET_URL` に書き出し先のスプレッドシートの URL を入れておくと、「本文を作成」で記事を作るたびに、そのスプレッドシートの「テスト出力」シートへ 1 行追加されます。WordPress が無いテスト中でも（`WP_MOCK` が `true` でも）記事を読んで確かめられます。

| 書き出す列 | 内容 |
|---|---|
| 実行日時・モデル・キーワード・タイトル | |
| 説明文（メタディスクリプション）・説明文の字数 | 120 字を超えると字数が赤字 |
| 本文の字数（見出しを除く）・本文（見出し付き） | 見出しは `## ` を付けて読みやすくしたもの |
| 本文（WordPress に送る HTML）・WordPress URL | |

- 書き出しに失敗しても下書きの保存は取り消さず、「エラー内容」に注意を書きます
- 本番で書き出しが要らなくなったら、`TEST_OUTPUT_SHEET_URL` を削除します
- 「作成済」の行は作り直さないので、同じ行で試し直すときはステータスを「タイトル案あり」に戻してからチェックを入れます

## 8. WordPress への送信を手元で試す（WordPress が無くても OK）

Apps Script は Google のサーバーで動くので、自分の PC の中の WordPress には届きません。送信の中身は、PC の中に仮の WordPress を立てて Node.js から確かめます。

```
node test/send-draft-test.js
```

- `gas/WordPress.js` と同じ関数で作ったリクエストを、仮の WordPress（`test/mock-wordpress.js`）に実際に送ります
- 成功・パスワード違い・権限なし・URL 違い・セキュリティプラグインに止められた・サーバーエラーの 6 通りを確かめます
- 届いた下書きの中身は `test/output/received-draft.json` に保存されます
- 本物の WordPress での確認（専用ユーザーで下書きを 1 本保存する）は、納品先のサイトができてから行います
