API キー設定手順書

最初に 1 回だけ行う設定です（約 20 分・管理者の方向け）

← 資料の一覧へ

この手順書でやること

  1. OpenAI の API キーを作る（AI に記事を書いてもらうための鍵）
  2. WordPress に記事保存用のユーザーとアプリケーションパスワードを作る（下書きを保存するための鍵）
  3. 2 つの鍵を仕組みに登録する
  4. 動作を確認する
  5. 鍵を安全に扱うために
API キーとパスワードは、お金や記事の保存に使える「鍵」です メール・チャット・スプレッドシートのセルには書かないでください。この手順書の「3」で登録する場所（スクリプトプロパティ）にだけ入れます。
画面の表記について OpenAI や WordPress の画面は、提供元の更新でボタン名や配置が少し変わることがあります。見つからない場合は、近い名前のボタンを探してください。

1OpenAI の API キーを作る

記事の文章は OpenAI（ChatGPT を提供している会社）の AI が書きます。ChatGPT の月額プランとは別の契約で、使った分だけ支払う前払い制です。

1-1. アカウントを作る

  1. ブラウザで https://platform.openai.com を開き、御社のメールアドレスでアカウントを作る（またはログインする）
  2. 電話番号の確認（SMS）を求められたら、画面の案内に沿って進める

1-2. クレジットを購入する

  1. 画面の設定から 請求（Billing） の画面を開き、御社のクレジットカードを登録する
  2. クレジットを購入する。最低 5 ドル から買えます（最初の金額が 10 ドルになっている場合は変更できます）
  3. 自動チャージ（auto recharge）はオフ にする
費用の目安 記事 1 本あたり約 7 円、月 13 本で約 100 円です（2026 年 11 月時点の料金表からの試算）。5 ドル（約 750 円）で半年分ほどになります。購入したクレジットは 1 年で失効し、原則として返金されません。

1-3. API キーを作る

  1. https://platform.openai.com/api-keys を開く
  2. 「Create new secret key」 を押す
  3. 名前（Name）に blog-autopost と入れ、ほかの項目はそのままで作成する
  4. sk- で始まる長い文字列（API キー）が表示されるので、すぐにコピー して、手順 3 まで手元に控えておく
API キーは 1 回しか表示されません コピーする前に画面を閉じてしまったら、そのキーを削除して、もう一度作ってください。

2WordPress に記事保存用のユーザーを作る

安全のため、管理者のアカウントは使いません。下書きの保存だけができる専用のユーザー を作り、そのユーザーの「アプリケーションパスワード」で接続します。万一パスワードが漏れても、サイトの設定や公開済みの記事は変更されません。

2-1. 専用ユーザーを作る

  1. WordPress の管理画面に、管理者でログインする
  2. 左のメニューの ユーザー → 新規ユーザーを追加 を開く
  3. 次のように入力して、ユーザーを追加する
    項目入れるもの
    ユーザー名blog-autopost など（あとで使うので控えておく）
    メール管理者が受け取れるアドレス
    権限グループ寄稿者（下書きは作れるが、公開はできない権限）
権限を「寄稿者」にする理由 この仕組みに必要なのは「下書きを保存すること」だけです。そこで、それ以上のことができない、いちばん弱い権限を選んでいます。万一アプリケーションパスワードが漏れても、被害を「下書きが増える」ことにとどめられます。
権限グループ下書きを作る記事を公開する他の人の記事を変えるサイトの設定を変えるこの仕組みでの扱い
寄稿者○×××これを使う。必要なことだけができる
投稿者○○××動くが、漏れると勝手に記事を公開されるおそれがある
編集者○○○×使わない。公開済みの記事まで書き換えられる
管理者○○○○使わない。漏れるとサイト全体を乗っ取られるおそれがある

寄稿者で作られた下書きは、御社の担当者の方（編集者・管理者のアカウント）が確認して公開します。「AI の下書きは、必ず人が確認してから公開する」という運用とも合っています。

2-2. アプリケーションパスワードを作る

  1. ユーザー → ユーザー一覧 から、いま作ったユーザーを開く
  2. 画面の下のほうにある 「アプリケーションパスワード」 の欄で、名前に blog-autopost と入れる
  3. 「新しいアプリケーションパスワードを追加」 を押す
  4. 4 文字ずつ空白で区切られた 24 文字のパスワードが表示されるので、すぐにコピー する（空白は含めたままで大丈夫です）
「アプリケーションパスワード」の欄が見つからないとき サイトが https で動いていない、またはセキュリティ用のプラグインがこの機能を止めている可能性があります。サイトの管理会社か、開発担当にご連絡ください。

32 つの鍵を仕組みに登録する

  1. 記事作成用のスプレッドシートを開き、上のメニューの 拡張機能 → Apps Script を開く
  2. 左の ⚙（プロジェクトの設定） を押し、いちばん下の 「スクリプト プロパティ」 まで進む
  3. 「スクリプト プロパティを編集」 を押し、「スクリプト プロパティを追加」 で次の 5 つを入れる
    プロパティ（左の欄）値（右の欄）
    OPENAI_API_KEY手順 1-3 でコピーした API キー（sk-…）
    OPENAI_MODELgpt-6.1-sol
    WP_BASE_URLブログのサイトの URL（例: https://example-saas.co.jp。最後の / は不要）
    WP_USERNAME手順 2-1 のユーザー名
    WP_APP_PASSWORD手順 2-2 でコピーしたアプリケーションパスワード
  4. 一覧に OPENAI_MOCK・WP_MOCK・TEST_OUTPUT_SHEET_URL があれば、削除 する（開発中のテスト用の設定です）
  5. 「スクリプト プロパティを保存」 を押す
大文字・小文字と空白に注意 プロパティの名前は表のとおりに入れてください。値の前後に空白が入らないように貼り付けます。

4動作を確認する

  1. スプレッドシートの「記事作成」シートで、空いている行にキーワードを 1 つ入れる
  2. 「② 使い方マニュアル」の STEP 2〜4 のとおり、タイトル案を作り、番号を選び、「本文を作成」にチェックを入れる
  3. 1〜2 分後、ステータスが 「作成済」 になり、「WordPress URL」に URL が入れば成功です
  4. WordPress の管理画面の 投稿 → 投稿一覧 に、その記事が 「下書き」 で 1 本あることを確認する

ステータスが「エラー」になった場合は、「エラー内容」の列の文言を「③ トラブルシューティング」で探してください。確認に使った下書きは、削除してかまいません。

5鍵を安全に扱うために

こんなときやること
鍵が漏れたかもしれない OpenAI：https://platform.openai.com/api-keys でそのキーを削除し、作り直す
WordPress：専用ユーザーのプロフィールの「アプリケーションパスワード」で取り消し、作り直す
作り直したら、手順 3 のスクリプトプロパティの値を書き換える
担当者が替わる・退職する念のため 2 つの鍵を作り直し、スクリプトプロパティを書き換える
使いすぎが心配OpenAI の請求画面で、使った金額と残高を確認できる。自動チャージをオフにしていれば、残高以上には使われない
スプレッドシートを共有するスクリプトプロパティは、スプレッドシートの閲覧者・編集者からは見えない。Apps Script を開ける人（編集者）は見られるため、編集者は必要な人だけにする
